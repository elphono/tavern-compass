# Reprise sur une autre machine — état au 2026-10-11

Tout le code, les tests, la doc et les décisions sont dans git (`main` à jour sur `origin`). Ce qui suit est ce que git
**ne porte pas**, et ce qui attend une décision. Le `CLAUDE.md` du projet reste la référence ; les issues GitHub, le
siège du travail en cours (`gh issue list -R elphono/tavern-compass`).

## 1. Préparer la machine

| Quoi | Pourquoi | Comment |
|---|---|---|
| WSL + SDK .NET 8, `gh` authentifié, `python3` | tests, builds, issues | `dotnet --version` ≥ 8 ; `gh auth status` |
| HDT installé côté Windows | builds de déploiement contre **la dernière version installée** (décision d'Ali du 2026-10-10) | `tools/hdt-install.sh` doit la trouver ; `tools/deploy.sh --dry-run` montre la cible |
| `lib/hdt/1.55.6/` | build de la CI et premier build | téléchargé seul au premier `dotnet build src/BronzebeardHud.HdtPlugin` (ignoré par git) |
| Hearthstone installé | build du mod anti-danse, tests de signatures | `-p:HearthstoneManagedDir=<jeu>/Hearthstone_Data/Managed/` ; `HEARTHSTONE_MANAGED=…` pour les tests ; dossier du jeu par défaut des scripts : `/mnt/e/JEUX/Hearthstone` (`--game-dir` ou `HEARTHSTONE_DIR` sinon) |
| `lib/bepinex/5.4.23.5/` | build du mod | téléchargé par le build du mod (archive officielle, SHA-256 du `.csproj`) |
| Bibliothèques complètes d'Unity pour BepInEx | sans elles BepInEx plante au préchargement (`GetPEKind`) | `tools/nodance-corlibs.sh` (éditeur Linux officiel, manifeste `tools/nodance-corlibs.sha256`) |
| `shellcheck` (facultatif) | contrôle des scripts | `sudo apt install shellcheck` |

Contrôles avant tout push : section « Façon de travailler » du `CLAUDE.md` (format, `dotnet test -warnaserror`,
`python3 tools/test_nodance_observe.py`, builds Release en `-warnaserror`, jugés sur leur code de sortie) ; autotest de
la simulation : `tools/BronzebeardHud.Harness/launch.sh --selftest`.

## 2. Ce qui vit seulement sur la machine de jeu (hors git)

| Où | Contenu | Sur une nouvelle machine |
|---|---|---|
| `%LocalAppData%\BronzebeardHud\stats\` | caches Firestone et nomi.gg, `nomi-state.json` (une tentative par jour), `manual\` (vide) | se reconstruit seul au premier lancement d'HDT ; ne jamais supprimer un cache à la main |
| `%LocalAppData%\BronzebeardHud\` | `layout.json` (place et taille des panneaux), `settings.json` (n compos), `patch-banner.json` | refaire la disposition par « Move panels » ; le reste se recrée |
| `%AppData%\HearthstoneDeckTracker\Plugins\BronzebeardHud\` | les deux DLL du plugin | `tools/deploy.sh`, puis relancer HDT |
| Dossier du jeu | BepInEx, `winhttp.dll`, corlibs, le mod anti-danse | `tools/nodance-corlibs.sh` puis `tools/nodance-deploy.sh` (refuse si le jeu tourne, sauvegarde datée, `--restore`, `--uninstall [--purge]`) |
| `<dossier du jeu>.nodance-backups/` | sauvegardes datées du dossier du jeu avant chaque installation du mod | propres à la machine |

**À refaire après toute mise à jour du jeu qui change sa version d'Unity** : les corlibs (sinon le jeu peut ne plus
démarrer ; retour arrière : `tools/nodance-deploy.sh --restore <sauvegarde>`). Rien ne le détecte automatiquement.

Branches locales non fusionnées laissées sur la machine d'origine (`feat/guide-bridge` et deux branches d'agents, 84 à
99 commits absents de `main`, d'avant la réécriture de l'historique du 2026-10-07) : rien à récupérer a priori, elles
ne sont pas poussées.
